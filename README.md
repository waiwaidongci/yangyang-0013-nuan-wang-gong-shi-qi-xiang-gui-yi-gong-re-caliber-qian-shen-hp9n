# 暖网公示 · 气象归一供热口径签审

青桥热网核算组有 9 名调度、计量和复核人员，为住宅与文教片区汇总每旬热耗。上游记录来自气象站日均温、热量表净供热日结及片区供热面积台账。此前人工合并 CSV 与工作簿，日期对齐和漏表难查，换基准温度时容易混用修订前后的热量，两版均算出时缺少可追溯的公示依据。这里以账期、片区、源表版本和口径并表支撑公示签审。签审凭证供站点调度与片区代表核对。

| 角色 | 典型页面 | 权限 |
| --- | --- | --- |
| operator | 账期与片区、逐日勾稽 | 登记自然日起止、片区面积、气温与供热日账，追加订正凭证 |
| reviewer | 口径并表、公示签审 | 登记不同基准温度，冻结源数据试算，签发一个账期公示 |
| viewer | 四页 | 浏览台账、片区数据、口径差异和签审凭证 |

## 一天的片区结算

1. 08:00 计量员打开 H-1123，范围为 2026-11-21 至 11-23。北岸住宅 32,000 m² 和南关文教 16,000 m² 组成核算范围。
2. 08:20 逐日勾稽按片区与自然日对齐 `wx-qingqiao-1123.csv` 和 `meter-daily-1123.csv`。
3. 08:40 南关文教 11-23 热量缺源，V-18 拒绝冻结，界面标出待补日账。
4. 09:10 找到南关文教原表并补录 21 MWh。两源齐后，复核员冻结 V-18 和 V-16 两种基准温度试算。
5. 09:55 同一快照并表，显示净供热量、面积加权度日、原始和归一单位面积热耗。如果基准设得过低使任一区度日为零，系统拒绝该口径。
6. 10:10 核对原表如有更正，按同日相同来源类型追加重订。旧计算仍可追溯，但与新版本快照不能并表或公示。
7. 10:30 使用最新台账重跑口径。复核员依据源表编号、覆盖天数和面积签发 NW-H-1123。
8. 11:00 片区代表查看公示热耗与签审人，核算范围、来源和公示版次保留冻结。

演示含缺一项热量的 H-1123 和已签发 H-1116。切换至 H-1116 可对照两个真实计算口径并查看签审。回归另建账期演示补齐、零度日、比较与订正。

## 口径计算

以片区为粒度，温度基准为 B，每天采暖度日为 `max(B − 日均气温, 0)`，账期片区度日为日度日之和。全区加权度日为 `Σ(片区面积×片区账期度日)/Σ片区面积`。原始热耗为 `Σ供热量(MWh)×1000/Σ面积`，归一热耗是它除以面积加权度日，单位 kWh/(m²·°C·日)。使用定点十进制处理单位换算并保存到 6 位小数。按自然日要求每区每天同时有气温与热量，任一区度日为零无法生成区级归一指标，冻结前给出具体缺源或零度日片区。归一口径适用于本模拟场景的参数敏感度比较。

每次计算冻结片区 ID 和各天两种来源的最后版本 ID。并表只接受相同 ID 集的不同口径。签审检查计算仍代表该期当前版本，防止报告在提交到公示前被后台修订。台账与签发均按账期加事务行锁。

## 启动与开发

```bash
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

[前端](http://localhost:18294) · [API 文档](http://localhost:19294/docs) · PostgreSQL 宿主端口 17794。账号 `operator@demo.local`、`reviewer@demo.local`、`viewer@demo.local` 的密码均为 `Demo2026!`。端口覆盖和连接环境变量见 `.env.example`。

| 服务 | 技术和职责 |
| --- | --- |
| frontend | Nginx 同源转发和原生 ES modules，`heat-book.js` 四页 |
| backend | FastAPI/Pydantic，`domain.py` 提供接口，`heat_book.py` 管理片区日账、冻结、并表和签审 |
| worker | Python 后台执行 `degree_days.py` 的面积、度日算法 |

| redis | Worker 依赖和健康探测 |

本地修改前后端后运行 `docker compose up -d --build frontend backend worker`。来源枚举 `weather, heat` 与快照阶段 `queued, ready` 出现在 `backend/schema.sql`、`backend/domain.py`、`backend/heat_book.py`、`frontend/heat-book.js`。角色和任务枚举见 `backend/core.py` 及 `frontend/base.js`。许可证见 [LICENSE](LICENSE)。

## 计量与公示跟进

- **累计表底**登记账期片区的计量表序列号、表盘清零上界及倍率。跨日首尾核对通过后，把差额或回零差额换算成 MWh。流水关联正式热量日账版本。接入累计表的片区从该入口追加热量，尚未接入的旧记录可继续手录。
- **采暖日情景**从一份已完成的归一快照读取冻结源账，登记启停日历后可换基准温度重算同时段运行热耗。没有开启日或片区度日为零时拒算。情景保留所用日历版本和计算快照，不影响已签审数据。
- **送达与异议**为已签公示的副本登记单位和发送渠道，人工录入送达凭证，然后受理来源、口径或措辞异议。文字纠正以补正单独编号发布，来源及口径问题可登记下期复查。原公示数字与签审证据持续保留。
